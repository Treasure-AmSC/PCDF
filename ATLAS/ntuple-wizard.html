ATLAS TREASURE → Parquet script wizard

Interactively select DAOD objects and variables, then download a custom Python script that writes each selected object to its own Parquet folder.

Choose the DAOD input

TREASURE includes PHYSLITE-like analysis objects plus additional content from the TREASURE derivation. PHYSLITE can be used directly, but jet constituent Particle Flow containers are not available there.

Generated script behavior

  • Uses uproot, awkward, numba, pyarrow, rich, and click, matching ATLAS/ntuple-maker.py.
  • Reads the selected branches from CollectionTree.
  • Writes selected table folders under one output root using tid=.../fileNumber=... Hive partitions.
  • Strips leading zeros from fileNumber so Hive partition readers infer it as an integer.
  • Encodes the file number into the leading 16 bits of generated indices so eventIndex, jetIndex, and related links are global within each tid.

Select output objects

Each checked object becomes a top-level table folder containing tid=.../fileNumber=... Hive partitions. Deselecting an object also deselects any objects that depend on it.

Choose variables

Variables are grouped by object. Four-vector components are required and cannot be deselected.

SLURM / NERSC Perlmutter

Generate a CPU-only sbatch wrapper for the Python converter. Input files must already be listed in the manifest before the compute job starts.

The generated job requests exclusive CPU nodes, discovers physical cores at runtime, counts the manifest entries, and fills the available cores with one conversion per core.
Defaults to the converter filename included in the downloaded bundle.
One local DAOD path per non-empty line. Create this manifest before submitting the compute job; the wrapper will not download data on compute nodes.

Review configuration

Local run: uv run ./ntuple-maker-treasure.py DAOD_PHYSLITE.37620644._000244.pool.root -o parquet-output (or ntuple-maker-physlite.py when PHYSLITE is selected). Output is written as table folders with tid=.../fileNumber=... Hive partitions; fileNumber has leading zeros stripped and is encoded into the leading 16 bits of generated indices.

  1. Create the input manifest listed on the SLURM page before submitting; the compute job never downloads data.
  2. Download the tar bundle, copy it to Perlmutter, and extract it with tar -xf pcdf-ntuple-bundle.tar.
  3. Return to a login node, ensure uv and GNU parallel are available, then submit with sbatch submit-pcdf-ntuple.slurm.
  4. Monitor with squeue -u $USER; inspect pcdf-ntuple-<jobid>.out, .err, and per-node GNU parallel logs in the generated run-helper directory if PCDF_KEEP_RUN_DIR=1 was set.
